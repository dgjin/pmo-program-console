# 对照最佳实践的评估与优化记录

版本：v1.38　评估日期：2026-11-03　范围：PMO 项目群管理台（`~/Downloads/PMO`）

## 一、评估基准

不看"功能多不多"，而是看这个工具是否覆盖项目群治理的关键动作，以及作为企业内网系统是否达到基本的安全与可用性门槛。基准取以下几类：

| 基准 | 用于判断什么 |
| --- | --- |
| P3O / MoP（Axelos 组合、项目群与项目办公室实践） | 治理结构、阶段关口、组合优先级、收益实现 |
| PMI《The Standard for Program Management》 | 项目群层面的收益、依赖、治理与干系人管理 |
| 主流 PPM 工具功能基线（Planview、Jira Align、Smartsheet 等） | 台账、关口、资源产能、组合报表的通用能力 |
| [OWASP ASVS 5.0.0](https://asvs.owasp.org)（2025-05 发布） | 认证、会话、访问控制、输入处理、安全响应头 |
| [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) | 对比度、键盘可达、焦点管理、页面标题、表单标签 |
| [NIST SP 800-63B](https://pages.nist.gov/800-63-3/sp800-63b.html) | 口令长度优先于复杂度、会话失效 |

评分采用 1–5 分：1 缺失，2 有雏形，3 可用但有明显缺口，4 覆盖主流实践，5 可作为标杆。评分是工程判断，不是审计结论。

## 三、这一轮实际改了什么

### 1. 阶段关口（治理缺口最大的一项）

- 新增 `gates` 表：项目、关口名称、阶段、计划/实际评审日期、结论（待评审/已通过/有条件通过/未通过）、评审人、条件。
- PMO 可新增与评审，项目经理只读；评审结论必填，未填不允许标记通过。
- 关口页按"待评审"优先，逾期关口标红；结论与条件写入审计日志。
- 总览的"两周内到期"把里程碑和关口合并排序，用标签区分。
- 演示库预置 27 个关口：15 个待评审、1 个未通过、1 个有条件通过。

### 2. 审核时效（SLA）

- 提交内容超过 **48 小时**未审核，在列表、图例、总览状态条和审核弹窗中标记"超时"。
- 侧栏待办数不变，但总览会显示"审核超时 N"。

### 3. 安全基线

- 所有响应加 `Content-Security-Policy`、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy`、`COOP`。
- 新增自助修改密码：校验旧密码、新密码至少 8 位、修改后其他设备会话立即失效。
- API 错误分级：业务校验返回 400 且不打印堆栈，未预期异常返回 500 并记录，避免用 400 掩盖程序错误。
- 保留既有能力：scrypt 加盐、会话 Token 只存哈希、HttpOnly + SameSite=Lax、登录失败 5 次锁定、写接口同源校验。

### 4. 可访问性（WCAG 2.2 AA 方向）

- 重新校准文字对比度：`ink-3` 从 3.90:1 提到 5.14:1，`ink-4` 从 2.38:1 提到 4.63:1，琥珀色从 3.82:1 提到 5.71:1。
- 弹窗增加焦点陷阱：Tab 在弹窗内循环，Esc 关闭后焦点回到触发按钮。
- 增加"跳到主要内容"跳转链接；每个视图更新 `document.title`；表头补 `scope="col"`。
- 保留 `prefers-reduced-motion`、`aria-live` 提示和可见焦点环。

### 5. 填报工作台（v1.3）

- 把周报/计划从弹窗改成独立写作页：左侧正文、右侧提交检查、项目现状、审核意见和历史版本。
- 停止输入 1.5 秒自动保存草稿；保存中、已保存、保存失败都有明确状态；离开页面前再存一次。
- 周报可带入台账进度、下阶段里程碑和未关闭风险；计划可复制上期内容，只填空字段，不覆盖已写内容。
- 每次提交把内容快照写入 `deliverable_revisions`，退回重提会生成第 2、3 版，PMO 审核时可展开对比。
- 新增 `deliverable_comments`：审核意见、退回原因、项目经理回复留在同一条记录里。
- 增加截止时间：周报周日 23:59，计划周期开始后 14 天；逾期未交在列表、统计和总览里标出。

### 6. Asana 对标（v1.4）

- **Timeline**：新增独立时间轴页，周/月/季缩放、计划与实际进度、里程碑菱形、今天竖线、周末底色、月份网格；左侧项目栏固定，打开自动定位今天。
- **Dependencies**：新增 `dependencies` 表和跨项目依赖，时间轴上用曲线连接上游交付日期与下游下一个里程碑，受阻画红线；PMO 可维护，项目经理只读。
- **My Tasks**：按角色汇总待提交/待审核、临近关口、14 天内里程碑和高敞口风险，按截止时间排序，审核任务显示已等待小时数。
- 未照搬：Rules / Forms / Goals。它们是另一个产品方向，当前优先补齐收益和决策台账更实际。

### 7. 项目工作台（v1.5）

- 原来的项目详情是“健康度 + 里程碑 + 风险”的静态页，周报和计划只在跨项目列表里按周期看。
- 改成项目页签：概览 / 计划与周报 / 里程碑 / 风险 / 关口与依赖 / 投入。
- 概览顶部四张行动卡：本周周报、本季度计划、下一个关口、高敞口风险，直接进入填写或审核。
- 计划与周报页签按项目列出最近 8 周和最近 4 个季度，包含状态、进度、提交人、审核人、版本数、沟通数；缺失周期可以补报。
- 新增 `/api/projects/:id/workspace` 一次返回项目、历史周报/计划、关口、依赖和截止时间，避免前端拼多个接口。

### 8. PMP 过程管理（v1.6）

- 按五个过程组做项目级检查表：启动（章程、干系人、立项关口）、规划（计划、里程碑、风险、预算与资源）、执行（周报、投入、进度同步）、监控（进度、高敞口应对、变更结论、EVM）、收尾（验收、经验教训、结项）。
- 新增 `charters`：章程草稿 / 提交 / 通过 / 退回，PMO 审批。
- 新增 `change_requests`：范围、进度、成本、质量等变更，项目经理登记，PMO 审批或标记实施；不自动改预算和计划。
- 新增 `lessons`：按知识领域记录背景、事实和建议。
- 新增 `#/process` 项目群过程矩阵，按完整度升序，直接定位最需要补齐的项目。
- 项目页新增「PMP 过程」页签，包含五过程组看板、EVM、章程、变更、经验教训。
- 新增 `/api/process-matrix` 和章程 / 变更 / 经验教训接口。

### 9. 清空与上线初始化（v1.7）

- 新增 `POST /api/admin/clear-demo`：清空全部业务数据和其他账号，只保留当前 PMO，项目群重置为默认空群。
- 保留当前会话，其他账号会话立即失效；操作要输入「清空」确认，并写入审计。
- 清空后总览、台账、时间轴、过程、里程碑、风险、关口、计划与周报、资源、报表都换成统一的三步引导，不再显示零值空表。
- 修复 `reload()` 未等待 `render()` 的竞态：清理后跳转总览会被慢返回的旧页面覆盖。

### 10. 双项目经理（v1.8）

- 项目经理账号增加甲方 / 乙方归属；项目记录 `vendor_pm_id` / `client_pm_id` 两个人，不再只是一个 `pm` 文本。
- 乙方项目经理保留周报、计划、里程碑、风险、投入、章程、变更、经验教训的维护权限；甲方项目经理只读，可评论，不能提交、不能审批。
- 甲方「我的待办」改为查看队列：乙方提交的周报和计划、临近关口和里程碑、高敞口风险。
- PMO 在项目台账里指定两位经理；乙方换人后旧经理立即失去维护权限。
- 修复项目详情路由吞掉 PATCH 的问题：以前编辑台账返回 200 但实际没写库。

### 11. 账号维护（v1.9）

- 用户列表增加搜索与角色 / 归属 / 状态筛选，显示负责项目、最近登录、在线会话数。
- 管理员可重置密码（生成随机密码并踢掉全部旧会话）、强制下线、删除账号。
- 删号有三道保护：不能删自己、不能删最后一个启用 PMO、仍担任项目甲方/乙方经理的账号不能删。
- 所有账号维护动作写入审计日志，密码本身不落日志。

### 12. 项目整体计划（v1.10）

- 新增任务级 WBS：阶段、任务、子任务，支持缩进/升级，阶段日期和进度自动汇总。
- 新增工作日排期和完成-开始依赖，支持多前置、循环检测；周末跳过，无法定节假日。
- 新增基线：保存当前开始/完成日期，改计划后显示灰色基线对照和时间偏差。
- 新增关键路径：按最长路径计算浮动时间，零浮动任务标红。
- 项目页新增「整体计划」页签，任务表与甘特图联动，支持新建、编辑、删除、缩进、升级、设基线。
- 乙方项目经理/PMO 可维护，甲方只读。

### 13. P0 数据同源（v1.11）

- 任务进度按工期加权汇总为项目进度；有整体计划的项目不能再手改项目进度。
- 周报当前周/未来周进度锁定为项目进度，并列出本周计划任务，可一键带入进展文本。
- 周报审核不再用周报百分比覆盖项目进度，避免和任务计划打架。
- EVM 的 PV 改为按任务基线计算“到今天应完成多少”，EV 使用任务汇总进度。
- 计划查询 GET 改为只读，写操作后重算；启动时校准一次。
- 反代 HTTPS 下自动加 Secure Cookie 和 HSTS；审计日志支持 CSV 导出。

### 14. P1 收益与行动（v1.12）

- 新增 `benefits`：基线、目标、当前、单位、方向、责任人、要求时间、状态；项目页自动算达成率和逾期。
- 新增 `actions`：来源（关口/变更/风险/会议）、优先级、责任人、截止日、状态；支持一键完成。
- 项目页新增「收益与行动」页签，PMO/乙方项目经理可维护，甲方只读。
- 当前值仍手工维护，没有接财务/业务系统；这是下一步自动取数的入口。

### 15. P1 验收与变更基线（v1.13）

- 新增 `acceptances`：交付物、阶段、项目三级验收记录，记录结论、确认人、时间、说明；交付物只能确认一次。
- 甲方项目经理和 PMO 可以确认，乙方不能代替甲方确认。
- 周报/计划审核通过后，甲方可在编辑页直接确认；项目页「收益与行动」集中展示验收记录。
- 变更审批增加“批准后更新计划基线”选项；选是则按当前任务计划重设基线，没有任务计划时拒绝。
- 所有动作写审计日志。

### 16. P1 关口检查清单（v1.14）

- 新增 `gate_checks`：每类关口默认 3 个必检项，支持未完成/已完成/不适用。
- 必检项未完成时，服务端拒绝“已通过/有条件通过”，避免关口结论没有依据。
- 关口列表显示完成数；新建关口自动生成模板，老关口可手动生成。
- 清单状态更新写审计日志。

### 17. P1 乙方供应商主数据（v1.16）

- 新增 `vendors`：编码、名称、联系人、电话、状态、备注。
- `users.vendor_id` 和 `allocations.vendor_id` 挂到同一家供应商；账号编辑和项目成员编辑都能选。
- 被引用的供应商不能删除，保留历史；管理维护显示账号数、项目数。
- 备份/导入包含供应商；账号和成员挂接不会因改名丢失。

### 18. P1 模板库与 Markdown 周报（v1.17）

- 新增 `templates`：项目周报、项目计划、里程碑、风险、关口、其他六类，Markdown 正文，每个分类一个默认模板。
- 管理维护可增删改、启用停用、设默认；默认模板不能直接删除。
- 周报编辑页自动带出默认模板，可手动套用其他模板；正文实时 Markdown 预览。
- 周报只填 Markdown、不填结构化进展时，提交自动提取摘要，避免多填一遍。
- 项目计划页、里程碑页提供模板参考入口。

### 19. P1 工作日历与任务实际（v1.18）

- 新增 `calendar_days`：法定假日、调休上班；排期函数已接入，改日历会重算全部计划。
- `plan_tasks` 增加 `actual_start`、`actual_end`、`vendor_id`；任务编辑可选乙方供应商并填实际日期。
- 任务行显示“供应商 · 实际日期”，实际日期不反向改计划日期。
- 管理维护新增工作日历页签，支持添加/删除。

### 20. P2 组合优先级（v1.19）

- 新增 `project_scores`：战略契合、收益、可行性、风险、投入五项 1–5 分，折算 0–100 组合分。
- 总览新增「组合优先级」，按分排序，显示评分依据；项目经理只读。
- PMO 可在总览直接调整评分，改动写审计。
- 新项目自动带默认 3 分，避免空值。

### 21. P2 指标周快照（v1.20）

- 新增 `metric_snapshots`：每周加权进度、平均健康、风险敞口、预算执行、收益达成、未关闭行动。
- 总览「指标趋势」显示最近 12 周、本周环比和明细表。
- 启动时自动补本周快照；PMO 可手动记录。
- 演示库 6 周历史快照标注“演示”，主库从本周开始积累，不伪造历史。

### 22. Markdown 扩展（v1.21）

- 表格支持列对齐、转义竖线、单元格内 `<br>`、行内格式。
- 支持脚注引用与文末回链，点击不改路由。
- 支持 Mermaid `flowchart TD/LR` 常用子集，渲染内联 SVG，回边走侧通道。
- 不支持表格合并单元格和完整 Mermaid 语法。

### 23. P2 资源需求 vs 产能（v1.22）

- 资源页新增未来 6 个月 FTE 需求表，按任务工期与月份重叠折算。
- 同一人多任务重叠会累加，超过 100% 标红，80–100% 标黄。
- 成员带乙方供应商，峰值单列。
- 仍缺自动资源平衡建议，只做识别不做调配。

### 24. P2 计划 CSV 导入导出（v1.23）

- 导出 WBS、父任务、工期、负责人、供应商、实际日期、前置关系，Excel 可直接打开。
- 导入支持追加/替换；替换清空基线，追加保留基线。
- 权限：PMO/乙方可导入，甲方只读导出。
- MS Project XML 仍未做。

### 25. P2 MS Project XML（v1.24）

- 导出 MSPDI 常用字段：任务名、WBS、层级、开始/完成、工期、完成比例、前置关系。
- 导入支持任务层级、工期、开始、完成比例、前置关系；自动识别 CSV/XML。
- 不导出/导入资源、日历、成本等高级字段。
- 仍是常用子集，不追求完整 MSPDI 规范。

### 26. P2 CI / 冒烟 / 压测（v1.25）

- 增加 `.github/workflows/ci.yml`，推代码自动跑接口测试、浏览器冒烟、轻量压测。
- `npm run test:ui` 用本机 Chrome + CDP，不引 Playwright，覆盖登录、侧栏收起、计划页、总览组合优先级、项目收益页。
- `npm run test:load` 84 请求/并发 7，输出 avg/p50/p95，p95 超 2s 或错误即失败；本机 p95 9ms。
- 仍不是完整 E2E，也没有渗透测试。

### 27. P2 安全基线与可访问性（v1.26）

- 修复项目工作台、项目详情、项目计划缺项目权限校验导致的越权读取。

## 四、仍然欠缺的部分（按优先级）

**P1，直接影响项目群治理**

1. **收益实现（Benefits）**：没有收益基线、目标值、当前值和责任人，无法回答"这些项目到底带来了什么"。
2. **会议决策与行动项**：变更和经验教训已有台账，但例会行动项还没有独立跟踪。
3. **附件与材料归档**：周报、计划、评审材料只能写字，不能挂文件。
4. **催办与通知**：靠总览提示，没有邮件/IM 提醒，跨时区团队容易漏。
5. **代填与委派**：项目经理请假时没有代理填报机制。
6. **甘特拖拽改期**：时间轴只读，改计划要去台账或填报页。

**P2，组合管理深度**

7. 组合优先级评分（战略契合、收益、风险、投入）。
8. 产能 vs 需求预测，而不只是当前负载。
9. 任务级资源平衡、任务成本、节假日日历和拖拽改期。
10. 关口检查清单模板、批量审核、评审委派。
11. 风险转问题、升级路径与升级时限。

**P3，平台化**

12. SSO / LDAP / 企业微信、MFA。
13. HTTPS 与反向代理部署样例、Cookie Secure。
14. CI（测试 + 静态检查）、容器化、自动备份、审计导出与保留策略。
15. 结构化日志、请求 ID、指标与告警。

## 五、验证方式与边界

- `npm test`：15 项全部通过（约 0.9 秒）。
- 响应头用 `curl -I` 实测；三个角色 × 9 条路由回归无控制台报错。
- 对比度用相对亮度公式计算，不是设计工具估算。
- 焦点陷阱用 CDP 连续 25 次 Tab 验证，焦点始终在弹窗内。

没有做的验证，不能算通过：读屏软件实测、渗透测试、压力测试、多浏览器兼容测试。

## 六、结论

这轮优化把最大的治理缺口（阶段关口）和最大的工程缺口（自动化测试）补上了，同时修掉了安全响应头、对比度和焦点管理这些"看起来没事、审计会挑出来"的问题。

但它仍然是一个**单团队、内网部署、以周/季度为节奏**的 PMO 工作台，不是 Planview 或 Jira Align 的替代品。下一步是否投入收益、依赖、决策台账，取决于你们项目群例会上真正缺的是哪张表，而不是功能清单还差几项。
