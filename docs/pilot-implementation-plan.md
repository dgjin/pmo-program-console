# PMO 项目群管理台试点实施计划

决策日期：2026-11-04  
基线版本：v1.40.0  
试点范围：当前系统已录入的项目和用户；不新增账号、不扩项目。  
技术方案：单实例 Node + SQLite，每日自动备份；其他企业级整改暂缓。

## 一、已确认的决策

1. **试点选当前系统录入的项目和用户**，不再拉新项目、不新建演示账号。
2. **接受单实例 SQLite + 每日备份**，不在这轮做 SSO/MFA、TLS 改造、HA、PostgreSQL、渗透测试等企业级整改。
3. 先跑 4 周试点，用当前真实项目验证流程和稳定性；试点通过后再决定是否启动企业级整改。

## 四、每日备份方案

### 4.1 已执行

- 备份脚本：`scripts/backup.js`
- 定时任务：macOS LaunchAgent `com.pmo.backup`，每天 02:00
- 备份目录：`backups/`
- 每次生成：
  - `pmo-<时间>.db`：`VACUUM INTO` 一致性快照
  - `pmo-<时间>.ai-key`：AI 配置解密密钥
  - `pmo-<时间>.json`：SHA-256、大小、来源、时间
- 保留：默认 30 天；`PMO_BACKUP_KEEP_DAYS` 可调
- 文件权限：备份目录 700，文件 600
- 日志：`backups/backup.log`

### 4.2 安装/重装定时任务

```bash
cd "/Users/dgjin/Downloads/PMO "
./scripts/install-daily-backup.sh
launchctl print "gui/$(id -u)/com.pmo.backup"
```

### 4.3 手动备份与校验

```bash
node scripts/backup.js
node scripts/verify-backup.js backups/pmo-<时间>.db
```

校验会做 `PRAGMA integrity_check`，并核对用户、项目、周报、会议、用品数量。

### 4.4 恢复演练

1. 停服务。
2. 把备份 `.db` 放回 `data/pmo.db`，删除旧 `-wal`、`-shm`。
3. 把对应 `.ai-key` 放回 `data/.ai-key`。
4. 启动服务，登录检查项目、周报、会议、用品。
5. 记录恢复时间和数据核对结果。

> 当前备份在本机 `backups/`，没有异机副本。单实例试点接受这个风险，但**磁盘损坏时备份会一起丢**；这不是企业级灾备。

## 五、4 周试点节奏

### 第 0 周：准备

- 发通知、确认账号、确认项目负责人。
- 做一次手动备份和恢复演练。
- 建问题记录表：日期、提出人、项目、问题、严重度、处理人、状态。

### 第 1 周：跑通主链路

- 每个项目确认计划任务、负责人、里程碑、关口。
- 乙方 PM 提交一次周报，PMO 完成审核。
- 周五复盘：哪里卡住、哪些字段不会填。

### 第 2 周：补齐数据

- 重点补计划任务进度、风险、行动项、收益指标。
- PMO 检查周报按时提交和审核时长。
- 会议/用品按需使用，不强制。

### 第 3 周：稳定性观察

- 看每日备份日志是否成功。
- 看有没有重复提交、权限、数据不一致问题。
- 做一次恢复校验（可恢复到临时目录，不动生产）。
- 周五中期复盘，决定是否继续。

### 第 4 周：试点退出评审

- 按第六节指标评估。
- 输出试点报告：使用情况、问题、数据质量、是否继续。
- 决定下一步：继续试点、扩大范围，或启动企业级整改。

## 六、试点成功标准

试点不是企业投产，标准要务实：

- 4 个项目都至少完成 2 次周报提交和审核。
- 周报按时提交率 ≥ 80%。
- PMO 审核在 48 小时内完成 ≥ 80%。
- 计划任务两周内更新过的比例 ≥ 60%。
- 没有数据丢失、没有越权访问、没有重复预订/超库存发放。
- 每日备份成功，至少做过 1 次恢复校验。
- 用户愿意继续用，主要问题有明确处理计划。

达不到就延长试点或停用，不硬推。

## 七、试点期间接受的限制

这些是企业级评审里的 P0，但本轮明确暂不处理：

- 没有 SSO/MFA，使用现有本地账号。
- 没有应用内 TLS；如通过反代访问，需要运维自行配 HTTPS。
- 单实例 SQLite，无 HA；数据库损坏时依赖备份。
- 每日备份在本机，没有异机/对象存储副本。
- 没有第三方渗透测试。
- 会议/用品已禁止自批；默认 PMO 可审批别人，PMO 自己的申请需要另一个 PMO 或审批员。试点前要创建一个审批员账号。
- AI 仍可能调用外部 DeepSeek，敏感内容不要贴进 AI。

**试点的前提**：只在内部网络/VPN 使用，不直接暴露公网 5177；PMO 每周看一次审计和备份日志。

## 九、试点退出后的选择

- **继续试点**：范围不变，延长 4 周，先修高频问题。
- **扩大试点**：增加项目/用户，但仍不做企业级全量。
- **启动企业级整改**：按 [企业级整改计划](enterprise-remediation-plan.md) 做 P0，再谈全量投产。
- **停用**：数据导出归档，保留备份，不再新增。

## 十、结论

这轮不追求“企业级上线”，只验证一件事：**当前 4 个项目、6 个用户，能不能用这套系统把周报、计划、关口和日常协作稳定跑起来。**

每日备份已经落地并验证过恢复；其余企业级能力等试点结果出来再决定，不在本轮扩张。
